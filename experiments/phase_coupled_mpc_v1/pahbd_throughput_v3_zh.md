# PA-HBD 双卡与单任务吞吐优化

基于41f347d，在独立工作树 pahbd-throughput-v3 实施。本轮没有恢复或启动正式训练；原A17的1824步checkpoint保留。所有实际数据实验只使用Hall合格train窗口；无test访问、无模型性能排名。

## 暂停语义

新版训练/队列终端内 Ctrl+C 可请求安全暂停；watch内 Ctrl+C 仅关闭监控。队列的PAUSE_REQUEST或control_pahbd_runs.py pause命令会请求所有当前任务安全暂停，并阻止后续任务启动。训练完成当前更新后保存，验证中则完成验证后保存；须等到paused，不能再强杀。加载数据阶段队列通过文件等待训练初始化，避免在信号处理器尚未安装时杀死子进程。

## 实现

- 双卡队列每GPU最多一个任务。workers_2gpu.json对应本机GPU0/CPU12与GPU1/CPU14（不同物理核），可选预取核16/17。六任务按A17/B17/A29/B29/A43/B43交错分配到两worker。任务各自CUDA_VISIBLE_DEVICES、日志、PID、checkpoint和状态独立，不做DDP/梯度聚合；固定采样、Adam更新与A/B结构合同不变。
- 队列一项失败则停止派发，并请求其余运行任务安全保存；区分failed/paused/completed。支持队列Ctrl+C和全局暂停文件。监控总体ETA取各worker剩余时长的最大值，不再将双卡队列全部相加。恢复准备入口沿用原任务worker资源。
- 固定相位系数的exp/expm1及固定gauge的sin/cos按dt/设备/dtype/张量版本缓存；输入控制、状态的可微路径保留。forcing/control谐波数相同时共享相位基函数计算。没有改变float64、积分步长、原始事件时刻或损失定义。
- 原生窗口在CPU完成构造，将观测/初始状态/控制张量打包为一次设备传输。控制仍使用原CPU规范化ZOH事件；无统一栅格、插值、补齐或监督删减。
- 可选最多两窗口的CPU线程预取：复制采样器用于lookahead，正式采样器仅在消费窗口时推进；预取不提前提交checkpoint状态。线程不运行CUDA，主线程负责设备传输。记录loader_seconds与主线程data_seconds，区分加载工作量与等待时间。预取不是默认开启，按本机实测决定是否使用。

## 编译结论

新缓存直接进入torch.compile时存在张量版本字典键导致的图捕获问题。绕开缓存测试纯数值核心后可得到1个图、0个图中断，但Triton编译仍报 `AttributeError: type object 'constexpr' has no attribute 'is_block'`。未更改依赖，未启用编译训练路径，没有编译提速结论。主要剩余成本仍是反向传播及大量串行小算子。

## 测量设计与限制

旧实现41f347d与新实现使用同一GPU0、CPU12、相同默认模型/float64、初始化和4个固定真实train窗口；A/B均分别测量。CUDA预热后显式同步，每组合2次计时，记录加载、历史重放、未来积分、loss、反向、优化器、CPU时间、CUDA elapsed及显存。CUDA elapsed包含主机提交间隙，不等于GPU kernel忙碌时间。不是所有航次的平均吞吐。

双卡实验每进程8次真实Adam更新（4时域各两次），预热与数据集初始化不计入稳定吞吐；两进程都完成预热后通过屏障同时开始。单卡预取开关使用相同采样顺序。双卡收益只指独立任务总吞吐，不代表单个模型加速，也不把GPU利用率当作速度。

详细原始记录在 `/home/zn/pahbd-runs/throughput-v3-20261103/`。启动新的正式训练仍需用户另行决定。

## 操作入口

在本工作树中，`prepare_pahbd_runs.py --workers configs/pahbd/workers_2gpu.json` 为原定六任务生成双卡资源分配；不加`--prefetch`时关闭线程预取。准备配置本身不会启动训练。`queue_pahbd_runs.py --run-root ...` 必须在独立tmux会话中运行且使用已提交的干净代码。两卡不同GPU、物理CPU核有启动前校验，但不是对外部任务的全局GPU资源锁；正式启动前仍须检查其他进程。

终端暂停：运行队列的终端按一次Ctrl+C，等待queue.json为paused；远程也可执行`control_pahbd_runs.py pause --run-root ...`。恢复用新目录与显式checkpoint，prepare-resume仅准备选中任务，不会自动恢复其它五任务。原始结果目录应保留，best记录可能引用它。

固定真实窗口前向预测和所有Loss分量完全一致；最大参数梯度绝对差4.44e-16。forcing/control梯度分支检查通过，B仍仅关闭显式control交互。新增缓存不涉及参数更新或过程噪声合同。

独立真实8步训练：GPU0串行45.388秒，GPU1串行45.075秒；两卡并发各46.012/46.018秒，总吞吐相对顺序运行提高**1.966倍**。两卡任务均使用A的相同初始化，仅用于吞吐与数值验证，不是正式A/B性能对比。预取关闭/开启分别45.388/45.614秒，未加速，因此默认关闭；主线程数据等待合计0.985/1.343秒，线程及GIL竞争抵消收益。五次短程运行的最终模型参数、窗口抽样顺序逐位一致。

八组时域/模式平均约5.468秒/步；按六模型各10944步及12次×156窗口验证粗算，单卡约104.8小时。双卡若训练与验证阶段均维持当前并发效率，则约53.3小时（2.2天）；**完整156窗口验证及双卡验证阶段未实测**，验证成本采用这4个train窗口的无梯度前向粗估，未计入完整验证指标汇总成本；仅单航次四窗口的计时不可作为完整训练完成时间保证，也未扣除已保存1824步。

峰值PyTorch已分配显存（不含CUDA上下文）从最大136.4MB降到115.8MB。细分CPU/CUDA elapsed、各阶段和每步数据成本见原始timings.json及concurrency/*.json。

## 回归验证

`test_pahbd.py`、`test_pahbd_performance.py`、`test_pahbd_resume.py`、`test_pahbd_throughput.py`：**62 passed**。包括SO(3)、原生ZOH分段、Hall/未来观测因果性、A/B控制分支、候选控制梯度、缓存失效、CPU/GPU暂停恢复、预取未提交状态、双worker设备隔离/并发/文件暂停/Ctrl+C/失败联动。完整测试输出保留在运行目录tests.log。

补充使用正式合格索引和seed17的前8次抽样，覆盖8个不同航次：关闭/开启预取分别36.547/36.898秒，仍未加速；最终模型参数及窗口顺序逐位一致。因此当前环境默认关闭线程预取的结论并非仅依赖单航次表缓存。上述数值只检验执行一致性与耗时，不用于任何模型优劣判断。
