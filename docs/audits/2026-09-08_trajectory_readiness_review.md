# 真实飞行轨迹神经网络：仓库进度与 9.6–9.8 数据审查

审查日期：2026-09-08。代码基线：`fcfeccb`，分支 `step5-actuator-aware-trajectory-main-v2`；开始时工作区干净。

本次核对代码、manifest、已有评估 CSV 和本地 checkpoint，并解析 24 个新 ULog。旧模型指标为已有运行结果的审阅，未重训或重跑预测。新日志分析是数据质量与输入兼容性审查，未证明预测精度提升；八月 sealed test 和四月 test 样本未读取。九月审计工具自动给出的 split 建议未采纳。

## 结论

仓库已经实现、训练并保存了短时轨迹预测神经网络。当前最可靠的结果是 0.5 s 历史观测驱动的 GRU，在另一天的五次飞行上预测未来 0.5–2 s。还没有证明一个可跨工况、跨控制策略泛化的控制条件动力学模型，也没有完成长航段轨迹或部署验证。不能给出有意义的单一完成百分比：短时观测预测已完成原型，控制响应辨识和长期泛化仍是研究缺口。

9.6–9.8 新数据值得进入下一轮实验。它增加了三个飞行日，尤其补充了 Hall 事件和有效的相位测量链。但舵机反馈仍缺失，控制工作点跨日漂移仍明显。优先完成数据契约与 Hall 消融，暂不扩大网络规模。

## 2. 已完成的能力与差距

`CausalHistoryTrajectoryModel` 用 64 单元 GRU 编码 26 个因果历史样本，预测机体系加速度、角加速度和扑频变化率，再通过刚体位置/速度与四元数积分滚动推进。训练目标使用 1 s 多步轨迹，已评估到 2 s。归一化只拟合 train；预测期间不喂入未来实际状态、扑频、相位、风或空速。

下表来自已有 validation CSV，指标为先逐日志计算端点 RMSE、再对五个日志等权平均，并非完整航程误差。

| 模型 | 时域 | 位置 m | 速度 m/s | 姿态 deg | 角速度 rad/s |
| --- | ---: | ---: | ---: | ---: | ---: |
| history only | 0.5 s | 0.200 | 0.658 | 6.45 | 0.731 |
| history only | 1.0 s | 0.540 | 1.113 | 10.45 | 0.755 |
| history only | 2.0 s | 1.975 | 2.283 | 18.98 | 0.782 |
| Main V2 gated | 0.5 s | 0.211 | 0.714 | 6.63 | 0.725 |
| Main V2 gated | 1.0 s | 0.586 | 1.169 | 10.67 | 0.744 |
| Main V2 gated | 2.0 s | 1.979 | 2.124 | 18.28 | 0.766 |

history only 相对无控制 ridge 的位置误差改善约为 0.5 s 的 25%、1 s 的 25%、2 s 的 14%。这说明神经历史编码确实有价值。

Main V2 在冻结的 history-only 基础上增加电机/尾翼一阶状态与受限残差。电机状态让 2 s 扑频 RMSE 从约 0.377 Hz 降至 0.196 Hz，却未带来一致的刚体轨迹增益。其正式 H1/H2 gate 为 false。不能将“最新版本”视为“轨迹精度全面最好”。

剩余缺口：

1. **控制响应的泛化**：未来动作的增益在 0.5、1、2 s 及不同日志间不一致。若用途是预测给定新动作后的轨迹，这是核心未完成项。
2. **数据独立性与覆盖**：训练有效飞行仅约 14.9 min、来自一天。窗口 stride=0.2 s，2 s 窗口高度重叠，4,214 个窗口不是 4,214 次独立实验。
3. **独立最终评估**：主结果来自五个验证日志、一个验证日；这一天已多轮用于方法诊断。当前正式实验使用固定种子，未提供多种子稳定性或最终 sealed-test 结果。
4. **时域与部署**：2 s 误差已明显增长，不能外推到 5–10 s 或完整航程。未来控制带仅在规划动作已知时可作为真实部署输入；纯观测预测和给定动作的动力学仿真需要分别验收。
5. **参考轨迹质量**：目标是 PX4 状态估计，而非独立运动捕捉真值，需要继续分开报告估计器质量和模型误差。

## 3. 主要瓶颈的证据

Step 4 的小型线性诊断也出现全部控制在训练上有益、验证上恶化，说明问题不能仅归于 GRU 容量不足。控制是闭环策略对飞行状态的响应，包含较强历史冗余；不同天的配平、执行器工作点、环境和策略变化会破坏这些相关关系。该解释受现有消融支持，但不是已经完成的因果证明。

旧八月数据没有 Hall，只有日志内相对相位。控制命令和 PWM 都不是实测舵面角，延迟、回差、负载和气动响应无法充分拆开。模型输入使用地速而非完整来流状态，也没有显式利用风/空速的因果历史；这是可检查的候选缺口，现有证据尚不能认定它是主要误差源。

## 5. 下一步顺序与验收

1. **登记九月数据契约**：明确机体/固件、四路分配、ratio、Hall 触发沿/物理姿态、时间戳、RPM 实例/单位、有效片段和整日 split。延续原八月 sealed test 隔离；九月自动 split 建议目前未采用。可预先考虑 9.6 作增量 train、9.7 作 validation、9.8 作冻结评估候选，但应先定数据用途，不做窗口随机划分。
2. **先测新增数据价值**：冻结原 history-only 和 Main V2，在确定后的新 validation 上做不训练的迁移评估；随后保持网络规模，比较旧 train 与加入新 train 的效果。分开“数据增量”和“结构增量”，按日、日志、机动和质量输出误差。
3. **再测 Hall 价值**：当前 extractor 把 `absolute_flap_phase_*` 固定为 NaN、`hall_reference_valid` 固定为 false，GRU 只用相对 `t0` 的相位。仅增加日志不会使用新 Hall 信息。需要一个明确版本的 Hall 数据路径，校验物理零点后，比较 history-only / history+Hall / history+Hall+受限控制残差，其他条件保持一致。
4. **检验控制是否带来跨日增益**：重做控制在历史之外的增量信息诊断，观察同一候选在 0.5、1、2 s 的逐日志增益；保留无控制基线与不确定性，不以单个平均指标或单日成功替代普遍改善。RPM/Hall 未来实测值只能监督，不能输入 rollout；因果初始/历史观测才可作为模型输入。
5. **数据不足时再补采**：优先跨天重复、分开激励电机/对称舵/差动舵/方向舵，并记录实际舵位、供电/电流及相关标定。这是针对闭环混杂与执行器状态缺失的补采建议，不是本次日志已经证明的原因。
6. **短时稳定后扩展时域**：先约定应用所需位置/姿态容差，再开展 5–10 s 和完整航段滚动、失败率及部署时延验证，最后按冻结协议打开最终测试。

本次最优先的工作是九月数据契约与 Hall 感知输入的受控实验。新增数据的数量和相位观测有明确价值；对轨迹误差的实际提升必须由上述跨日对照实验给出。
