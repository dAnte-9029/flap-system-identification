# VelocityRateGRU 控制事件统一规则

规则 ID：`exact_zoh_merge_us_v1`。适用于 `velocity_rate_multistep_v1` 的整数微秒、分段常值四路命令接口。它规范化日志重建控制函数，不宣称该函数是未经漏采的实际执行器输入。

## 表示与保证

输入 `events[..., E, 5]`：电机、左舵、右舵、方向舵、持续时间（秒）；`event_length[...]` 指定有效前缀。前导维度分别代表窗口、状态区间等独立单元。各单元内四路值使用其输入存储精度精确比较，不使用近似相等阈值。

1. 忽略有效长度之外的 padding。
2. 持续时间恢复为整数微秒。允许的 0.05 微秒偏差仅用于接收 float32 存储舍入，不是改变时间或合并控制的阈值。拒绝不能表示的正亚微秒段、负时长、非有限有效值、越界长度。
3. 删除零时长条目；合并相邻且四路完全相同的条目，以整数微秒累加持续时间。
4. 保留所有真实控制变化及其相对区间起点的时刻。不跨越状态区间、窗口或飞行边界合并。
5. 重新计算有效长度，padding 清零，张量宽度取批次中最大规范段数。零时长的无效状态步保留一个全零占位条目。
6. 模型入口核对持续时间总和等于该状态步的 `dt`，按同一整数时钟比较。

对同一个状态时间网格、同一个分段常值四路函数，此规则得到相同的有效序列。相同批次中即使上游事件条数和 padding 宽度不同，规范张量也相同。不同批次形状/设备之间仅承诺相同有效序列，不承诺底层 GPU 运算逐比特一致。

重复消息必须只表示同一命令继续保持；如果它包含重置、看门狗或其它协议动作，当前四路数值接口不足以表达该动作，不能用本规则消除其语义。

## 统一入口

- 唯一实现：`src/system_identification/models/control_events.py` 的 `canonicalize_control_events`。
- 数据打包：`scripts/prepare_velocity_rate_learning.py::interval_events` 默认调用同一实现的 NumPy 适配器；不修改注册数据集中的原生记录。
- 模型入口：`VelocityRateGRU.forward` 默认再次规范化未来控制。这是幂等操作，确保旧缓存、调用者自造的事件及交换控制路径也受保护。GRU-NoControl 不读取或检查控制值。
- 新训练 checkpoint 的 `config.control_event_policy` 及评估契约记录规则 ID。参数数量、state_dict 键、历史 GRU、事件 GRU、状态递推 GRU、相位外推和积分方式均未改变。
- 历史 500 ms 控制仍按历史状态时刻与运动状态一起输入；本规则处理进入 event GRU 的未来控制段，不改变历史特征契约。

示例：`[U, 5ms][U, 7ms][V, 8ms]` 规范为 `[U, 12ms][V, 8ms]`，保留 12ms 的真实跳变。不存在把整个 20ms 强行平均或只取起点值的操作。

## 旧权重、旧结果与重现

旧权重可直接 `load_state_dict(..., strict=True)`，默认使用新规则；不会根据旧 checkpoint 缺少规则字段就自动退回旧语义。旧缓存只在内存中规范化，不覆盖文件。

完全重现历史原生结果时应使用原实验提交。局部诊断可显式创建 `VelocityRateGRU(..., control_event_policy="legacy_raw_v0")`；这会跳过规范化，是明确标记的历史模式。打包器也提供同名 `event_policy` 仅供历史重现。新训练入口拒绝非规范策略。

历史实验报告、指标、权重及数据缓存保持冻结。不要直接运行以旧实验目录为输出目的地的历史脚本来生成新结果；新运行应使用独立实验输出位置并记录规则 ID。改变后产生的指标不能混入旧表中。

## 验收与能力边界

验收见 `experiments/control_event_canonicalization_v1/`：冻结三个种子、全部 36,332 个验证窗口、原有八个异常窗口、二分/四分/随机拆分、实际命令交换，以及真实轨迹误差和独立复算。该规则解决同值冗余分段，不保证漏采控制可恢复、对近似小扰动连续，也不证明反事实控制响应准确。
