# 参考模型重力特征单位不一致：诊断与修复

2026-09-27，在执行五步研究计划的实现核对中发现。

`prepare_reference_dynamics_data.py` 将 `[0,0,1]` 旋转到机体系，保存的是**单位重力方向**。原 `ReferenceGRU` 的滚动状态由公共函数 `_state_features` 生成；该函数将 `[0,0,9.80665]` 旋转到机体系，生成的是**重力加速度**。原参考模型将两者直接套用相同的 state_mean/state_scale。

这不是需要从日志辨识的物理差异，而是参考模型实现中的特征单位错误。所有 1146 个样本起点的历史重力向量模长中位数为 1，原解码器为 9.80665；对解码器对应三维除以 9.80665 后，与历史字段的最大差异约 1.2e-7。

此前测试覆盖了未来信息边界、四元数归一化、有限梯度、窗口边界等，但没有检验“预测起点重新构造的状态特征与记录历史特征完全同义”。已补充这个回归测试，并对全部样本重建特征逐项检查。

为保留可复现性，原 `reference_gru.py` 和 v2 / v3 legacy 结果不改写。修复版为 `ReferenceGRUUnitGravity`，保留相同网络结构、40070 参数、初始权重和损失，仅统一重力方向单位。checkpoint 写入 `feature_contract=unit_gravity_v1`，专用加载器拒绝单位契约不匹配的文件。

原 A/B/C/D 比较仍描述那个旧实现下的数据策略结果；它不能用来证明旧日志缺少控制信息，亦不能视为充分检查了正确实现模型的能力。尤其是早期“保持未来参考影响很小”的诊断，必须在修复后复查。新采样清单只依赖输入数据，未受此模型实现错误影响，可以保持冻结。

修复后重新执行同预算 A/B/C/D 和 A800→A1600 单因素对照。正式结论入口为本目录 `unit_gravity/` 下的训练、评价和响应诊断；旧结果仅保留为实现问题的证据。
