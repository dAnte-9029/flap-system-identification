# 第二阶段：控制链回放与输入响应证据

已完成本阶段的控制链数值核对、注册数据输入事件筛选，以及固定 2 Hz 因果低通的敏感性检查。**可以继续完善现有 PX4 的仿真接口，但目前证据不足以进入“用模型优化尾翼控制器并宣称可信”的阶段。** 电机指令→扑翼频率已有方向支持；尾翼→角运动的独立增益、延迟仍未被本次检验约束。这个结论是“本次检查未建立足够证据”，不是证明闭环日志无法用于任何系统辨识方法。

## 1. 做了什么、使用什么数据

- 控制器按 e624a99f2955addbf76681e636c44162a0c03055 源码及 9.18 三份日志的实际参数回放，外部 PX4 工作区未修改。
- 输入响应使用注册 trajectory_v2_september_phase_observed 的 6 条 train、9 条 validation，manifest 和全部 26 个样本/窗口文件重新核验；15 份源 ULog 也与 manifest 哈希相符，只读取所需 topic 以确认信号年龄/间隔。
- 所有控制器输入保持 backward as-of 对齐，不通过未来样本插值构造控制输入。事件曲线是事后响应可视化，其观测目标允许插值；这不是在线控制输入。
- 原封存测试、9.19 候选均未打开。没有新训练，没有在九月数据上套用八月 S0/S1，也没有做自主动力学闭环仿真。
- 主要脚本：`scripts/audit_control_readiness_stage2.py`；外环补充：`scripts/audit_control_readiness_stage2_outer.py`；带宽敏感性：`scripts/audit_control_readiness_stage2_bandwidth.py`。

## 2. 控制链已核对到什么程度

### 2.1 姿态外环

复现了目标源码中的 Euler 姿态误差、时间常数、协调转弯 yaw 项、Euler→body 角速度转换和限幅。只对自动航线段评分，排除手动 yaw 叠加；按日志记录更新率递推上一周期 yaw Euler 设定值。因此仍是记录网格上的近似，不是飞控调度逐周期等价执行。

|9.18 日志|Roll 角速度设定值 RMSE|Pitch 角速度设定值 RMSE|Yaw 角速度设定值 RMSE|
|---|---:|---:|---:|
|log_0（A）|0.00299 rad/s|0.00357 rad/s|0.000115 rad/s|
|log_1（B）|0.00307 rad/s|0.00531 rad/s|0.000221 rad/s|
|log_2（B）|0.00298 rad/s|0.00406 rad/s|0.000284 rad/s|

Pitch RMSE 约 0.20–0.30°/s，但最大单点差异仍达 0.059–0.124 rad/s，不能只看均值就宣布完全一致。结果见 `outer_loop_metrics.csv` 和逐点 outer_replay CSV。

### 2.2 角速度内环

分别核对三种不同层次，不能混淆：

1. **日志算术自洽**：P+I+D+FF 与记录 output 差异在 float 数值精度量级。这只证明诊断字段的语义和求和关系。
2. **条件回放**：从记录角速度/设定值计算 P、FF，同时使用日志内部 I 和 gain。不是独立控制器；俯仰转矩指令 RMSE 为 0.00890–0.00953。
3. **俯仰状态递推回放**：仅首个可用点用记录 I 初始化，此后积分、空速一阶滤波（源码时间常数 1 s）、振荡增益压缩自行更新；仍读取实际状态、设定值、低频分配器饱和反馈。前 5 s 不评分，但保留递推和曲线。不是自主飞行动力学仿真。

|日志|状态递推输出 RMSE|绝对误差 P95|最大绝对误差|
|---|---:|---:|---:|
|log_0|0.01341|0.02458|0.18369|
|log_1|0.01418|0.02482|0.11512|
|log_2|0.01151|0.02163|0.19042|

单位均为归一化 pitch 转矩指令，不是 N·m。实飞 FW_GC_EN=1，不能省略增益压缩；状态递推 gain 与低频记录 gain 的 RMSE 约 0.024–0.028。只有约 94.9%–96.3% 的 rate_ctrl_terms 对应 gyro 样本在日志中精确存在，角速度设定值 as-of 年龄 P95 约 24.4–24.8 ms；饱和反馈仅约 5 Hz。初始隐藏滤波状态和未记录的控制更新也没有完整恢复。这些是剩余误差的候选来源，本次没有证明每项贡献。

B 组 Roll 只做了“日志 PID 输出 + 日志转移状态 + 日志有效增益”的条件合成，RMSE 约 0.0020–0.0026；**没有重建整个 B2b 状态机**。不能把该误差当成 B 组完整自主控制器等价性结果。

### 2.3 控制分配与输出

当前未饱和、零 trim/flap/spoiler 条件下的软件关系为：

```
left  = pitch_torque / 2 - roll_torque / 1.1
right = pitch_torque / 2 + roll_torque / 1.1
rudder = yaw_torque
symmetric_tail    = (left + right) / 2
differential_tail = (right - left) / 2
```

尾翼分配后有 [-1,1] 限幅，饱和时不能继续用未限幅逆关系恢复转矩。左右舵机回放 RMSE 为 0.00060–0.00125，P95 约 1e-7，说明主体映射能对上；少数不同步点最大仍约 0.069。

MAIN1 反向、MAIN2 正向、MAIN5 反向，与 PWM_MAIN_REV=17 一致。中位和幅值按各通道 min/max 计算。舵机→PWM 的 RMSE：MAIN1 约 6.7–8.1 μs，MAIN2 约 5.8–10.4 μs，MAIN5 约 2.0–4.2 μs；电机 MAIN3 在有效非负命令范围约 1.7–2.0 μs。

**不能忽略峰值：**MAIN1 最大差异约 551 μs，发生在 log_1 转 Manual 时，源舵机命令约旧 10.1 ms；另一些大误差在模式切换或日志起始。`PWM_worst_cases.csv` 保留这些点，没有从总表中删掉。该证据支持异步/切换问题需进一步核对，不能证明所有差异都仅由延迟造成。

上述均为输出命令链核对。没有实测舵角、翼载荷或引脚波形，不能据此确认物理安装符号和执行器实际滞后。

## 3. 输入响应：先固定规则，再看验证数据

原始输入筛选用每 0.2 s 一个候选起点，检查 [-0.5,+1] s。全窗要求状态/控制/飞行/相位有效、模式不变、无估计器重置，必要原始 topic 的发布年龄和间隔不超过 50 ms。低频控制器空速/饱和反馈不套用此事件规则。

从 train 有效候选计算并冻结：

- 当前地速约 5.03–8.99 m/s、俯仰约 9.02–26.28°、频率约 3.01–4.26 Hz，分别来自 train 的 P5–P95，**不是已验证的安全飞行包线**。
- 输入变化量为后 0.2 s 均值减前 0.2 s 均值；激励至少为 train |变化量| P75，且不小于 0.01。对称尾翼阈值约 0.02117，差动约 0.08523，电机约 0.01298，方向舵约 0.01692。
- 其他通道全观察窗内变化不得超过 train 相应幅度 P25（下限 0.01）；目标通道事前波动≤激励的一半，后续 0.2–0.5 s 保持同方向至少一半变化量。
- 同一通道每飞行保留事件间隔≥1.5 s；所有候选、排除原因都保存。未按结果放宽规则。

这些是“近似独立且可解释的事件”规则，不是神经网络训练数据准入的通用标准，不应直接删除所有不合格片段再训练模型。大量连续耦合数据仍可能对预测有用。

|输入通道|原始 train 事件（涉及日志）|原始 validation 事件（涉及日志）|判断|
|---|---:|---:|---|
|对称尾翼|0（0）|1（1）|没有可跨飞行复核的独立俯仰响应|
|差动尾翼|4（4）|4（2）|数量少；0.5 s 原始 Roll 响应在 train 正负混合、validation 全为负；不能解释为真实控制效能符号|
|电机|4（3）|9（6）|13 个事件在 0.5 s 的频率变化与指令同向，支持“指令→频率”的方向|
|方向舵|0（0）|0（0）|本规则下无可用独立事件|

电机 apparent gain 的 0.5 s 范围为 train 3.34–18.97、validation 2.10–29.07 Hz/归一化指令，离散很大，且前段趋势、负载和闭环条件未严格匹配。不能直接拿它当传递函数增益，也不能证明电机→推力/加速度，更不能据此确认模型中 0.10 s 执行器常数。

原始对称尾翼多数有效窗因为事前快速波动而失败（train 3371 个有效候选中 3347 个不满足稳定事前输入）。为避免把“严格原始阶跃为空”误说成“控制带宽内没有信息”，补做固定 2 Hz 一阶因果低通**命令**的敏感性检查；时间常数约 79.6 ms，状态按有效段重置，保留至少 0.5 s 历史，响应仍报告原始观测。其阈值另外仅由 filtered train 固定。该补充是在查看原始结果后提出，明确属于探索性检查，不冒充预注册主检验。

|对称尾翼|2（2）|11（6）|

低通后对称尾翼的 0.5 s 原始响应符号仍不一致（train 正 1/2，validation 正 6/11）。此时不能从单点原始角速度中识别稳定增益/延迟；也没有通过更平滑的曲线来宣布控制有效。低通输入事件不代表其他通道的原始高频输入真的恒定。两种筛选共同支持的只是：当前直接事件验证仍不足，需更完善的闭环辨识或专门激励。

## 4. 下一步明确选择

**先修控制回放的时序/隐藏状态契约，并补尾翼响应证据；不以增大网络替代这两个缺口。**

1. 已经可用的工作基础：e624 姿态外环公式、俯仰内环含空速滤波/增益压缩的记录网格实现、实际分配/PWM 映射、日志对齐诊断。下一步将其整理为仿真控制接口之前，保留 mode/reset 边界与不同频率时钟；不是把控制器和模型都强制改为 50 Hz。
2. 对称尾翼优先补证据：采用原稳定控制算法下可记录的参考激励或明确位置的小扰动，记录外生激励与实际输出，并用重复、正负平衡试验区分机体扰动和控制器补偿。具体草案在 `identification_followup.md`。
3. 电机→频率可以继续做端到端局部模型诊断，但不能直接转为完整飞行动力学可用结论。
4. S0/S1 保留原身份；未因这轮控制器回放推断其动力学精度。新九月模型仍须同数据匹配基线及 0.5/1 s 自主预测评估。此次尾翼证据门槛未过，不进入控制器优化或实机新算法部署。

绝对姿态/速度误差预算仍未冻结。不能从本轮 0.013 的控制输出回放误差推导“动力学允许误差”；也不能从单一有效俯仰事件反推稳定的任务幅度预算。
