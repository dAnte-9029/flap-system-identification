# 角速度测量与时间对齐审计

## 核心结论
缓存角速度与原始日志按冻结规则对齐的结果完全一致，未发现角速度拷贝或单位变换错误。仅将发布时间对齐改为位置采样时间约束，差异很小，不能据此解释此前较大的滚转快速残差。但是，同一状态行内姿态与角速度并非同一采样时刻，且降采样没有额外抗混叠滤波。这两点仍限制快速响应的解释；本轮没有证明残差是传感器噪声，也没有证明修正对齐就能解决持续操纵响应。

## 范围与来源
只读原 trajectory_v3_september_expanded 的17架 validation飞行和显式准入的3架Sep18开发飞行。后者属于train。本轮没有读取Sep8/Sep19数据或测试指标，没有训练、推理、修改模型、标签或控制器。该数据集为明确指定的历史轨迹数据，不是新选取的canonical数据。

逐日志核验原manifest中的SHA256，核验train/validation缓存哈希。分析覆盖所有valid_core行，不是先前2582个origin的重新评价，也没有按模型误差筛选。本轮比较不使用模型预测。原始日志初步检查早于protocol生成，protocol如实记录，不称盲法预注册。两次工程停止和处理见engineering_notes.md，原访问记录保留。

## 方法
原规则：在位置消息发布时间t，取最后一个发布时间≤t的角速度，freshness=50ms。逐行复算与缓存p/q/r精确相等，包括非核心行的NaN。

固定敏感性规则：位置的timestamp_sample为参考，选择采样时间不晚于该参考且发布时间不晚于原状态行的最新角速度，采样龄期≤50ms。它只是两个确定性对齐规则的差异，不是真实误差改进。没有搜索最优时移、拟合滞后或修改旧预处理。

下表时间差是“每架flight中位数”的等权平均；敏感性是“每架flight轴向RMSE”的等权平均。没有将行当独立统计试验。全部154225个valid_core行均满足共同比较条件，未因数值差异排除行。

## 记录频率与滤波链
20架日志均记录vehicle_angular_velocity和主sensor_gyro约99.71–100.00Hz，vehicle_attitude及vehicle_local_position约49.86–50.01Hz。IMU_GYRO_RATEMAX=400是发布上限配置，不是日志实际400Hz记录。所有已检查主题的发布时间严格递增，无重复/倒序；详细间隔和尾部值见topic_timing.csv，不能把非均匀网格写成严格50Hz。

全部日志初始IMU_GYRO_CUTOFF=40Hz，IMU_DGYRO_CUTOFF=20Hz，静态notch频率为0，动态notch enable为0，所查参数无运行中变更。三个实际固件commit的VehicleAngularVelocity.cpp均能在本地读取，文件hash相同。源码确认xyz经过角速度低通、坐标校正、标定及偏置扣除；20Hz DGYRO滤波作用于角加速度，不能当作角速度的20Hz低通。源码行证据见firmware_*.txt。

约100Hz的日志角速度被过去值保持到约50Hz状态网格，冻结管线没有为这一步增加抗混叠滤波。40Hz低通不构成针对名义25Hz Nyquist的充分抗混叠保证。由于时间步不均匀，不能直接套严格均匀采样的25Hz硬边界，更不能仅凭此断言已发生严重混叠。

## 同一行的时间含义
validation中，角速度采样时刻通常比位置采样时刻早约4.96ms；角速度比所选姿态采样时刻新约12.39ms。各flight内后一差值的p05约7.39–7.49ms、p95约24.64–24.95ms，不能把一行状态视为严格同步测量。该差值主要反映独立发布节奏与过去值保持，不等于物理执行器延迟。timestamp_sample也不揭示所有滤波/估计群延迟。

位置发布相对采样时刻仅约0.55ms，因此对位置采样时刻重新约束，validation平均只有约0.056%行更换角速度消息；这解释了敏感性很小。该结果不能排除姿态与角速度时刻差造成的误差，更不能从模型误差中直接减去上述RMSE来估计“测量噪声占比”。

Sep7缓存保留state_sample_timestamp_us；Sep17/Sep18缓存该字段为NaN，但原始日志存在对应时间戳。本轮从raw读取审计，未补写缓存；已有字段的对应关系已精确核验。这是追溯信息缺失，不能直接认定模型输入错误，该字段本来就不是模型输入。

## 目前能与不能解释的问题
此前滚转快速残差偏大，与这次“发布/位置采样时刻替换”产生的很小差异不在同一量级。但前者是high-control预测区间统计，后者是全valid_core行的标签差异，不能把两者当作同一分母进行因果归因。

主sensor_gyro只记录约100Hz；第二陀螺约1Hz，vehicle_imu约2Hz，本轮未发现记录的sensor_gyro_fifo。现有日志不足以重建完整高频振动、内部滤波输出或可靠估计噪声底。sensor_gyro还涉及传感器坐标/标定，与vehicle_angular_velocity直接相减也不构成真值误差。

因此不能宣称“模型持续操纵响应问题只是测量噪声”。尤其此前偏航低频响应偏弱，不能由本轮很小的位置时间基准差直接解释；模型输入响应、自由递推误差与观测链仍需分别检验。

## 下一步建议（未执行）
先做一个仅限开发数据的固定观测链敏感性诊断：在相同origin上，明确保留各状态的sample timestamp，比较严格共同测量时刻及预先规定抗混叠处理下的快速波形；原始标签指标必须并列保留，不能用平滑后的较好分数替代。使用现有冻结预测即可先排查评分对齐敏感性，不训练或重调tau，不按误差搜索最佳时移。

如果该诊断仍不能解释滚转快速误差，再设计专门实飞输入激励。届时需同步高频记录选中IMU原始/FIFO、滤波后角速度、姿态采样时间、实际舵机反馈与命令，结合安全的小幅正负激励。现有孤立rudder片段少且方向不全，不足以校准持续偏航因果响应。这里只建议，不启动实飞、控制器修改或新训练。
